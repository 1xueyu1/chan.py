# btc_futures_v2_bsp2_family 工作回顾

更新时间：2026-06-04

这份文档用于快速回忆 `btc_futures_v2_bsp2_family` 这条路线之前做过哪些工作、当前保留了什么、哪些东西已经验证过但不再作为主线。

## 1. 路线目标

这条路线是在 `btc_futures_v1` 标准二类买卖点基础上扩展出来的。

最初的问题是：标准二类买卖点虽然相对纯，但交易频率偏低。于是这条路线尝试把“标准二买/二卖”扩展成“二类买卖点族群”，在保持更多交易事件的前提下，用模型和结构风险定仓区分信号质量。

当前正式目标：

```text
围绕 15m 二类买卖点族群，提高交易频率；
保留第三段确认后的盈利路径；
重点压制确认前结构失效带来的亏损。
```

## 2. 当前保留口径

当前正式基准是：

```text
decision_realtime_v2
```

核心口径：

- 入场信号来自 15m 二类买卖点族群。
- 入场时间使用信号可用时间，不额外推迟 15m。
- 默认不使用旧概率硬过滤，避免过度压缩交易频率。
- 出场使用 `family_realtime` 实时状态机。
- 第三段确认后等待 15m 同级别任意反向买卖点 `opposite_bsp` 出场。
- 使用二级决策模型识别结构身份、确认前失效风险、后续路径概率。
- 使用结构风险定仓处理低质量信号，而不是直接删除信号。

## 3. 候选信号扩展

候选生成位于：

```text
ML/routes/btc_futures_v2_bsp2_family/candidate_family.py
```

当前候选族群：

| 候选 | 含义 |
|---|---|
| `standard_bsp2` | 标准二买/二卖 |
| `subclass_bsp2s` | 类二买/类二卖 |
| `bsp2_t3_overlap` | 二类与三类买卖点重合或接近重合 |
| `bsp2_after_bsp1` | 一类买卖点之后的二类确认形态 |
| `bsp2_near_origin_zs_boundary` | 原中枢边界附近的二类确认 |

这一步解决的是“交易次数太少”的问题，但也带来了更复杂的坏结构识别问题。

## 5. 特征扩展

当前特征主要来自：

```text
ML/routes/btc_futures_v2_bsp2_family/features.py
ML/shared/structure_features.py
```

做过的特征方向：

- 笔相关特征：笔强度、笔位置、笔幅度、笔年龄、前后笔幅度对比。
- 中枢相关特征：是否在中枢内、距离中枢上下沿/中轴、原中枢边界对齐。
- 买卖点上下文：买卖点在父线段/当前笔中的位置。
- 多周期结构：1h、4h、1d 方向一致性、冲突、边界、成熟度。
- 区间套/背驰结构：小级别背驰是否嵌套在大级别中枢边界附近。
- 技术确认：MACD/均线/布林带/成交量/波动率/趋势效率等派生确认。
- 市场状态：趋势、震荡、高低波动、交易时段等辅助特征。

其中 `ML/shared/structure_features.py` 是从旧实验路线迁移出来的通用结构特征能力。里面仍有一些 `v3_` 前缀列名，这是为了兼容现有模型的 feature columns，不代表还保留旧路线。

## 6. 模型结构

训练入口：

```text
ML/routes/btc_futures_v2_bsp2_family/train.py
ML/routes/btc_futures_v2_bsp2_family/decision_models.py
```

做过两层模型：

第一层：入场质量模型

- 按多空方向拆分。
- 按二类买卖点族群拆分。
- 输出每类候选的入场质量概率。

第二层：二级决策模型

- 学习 `label_bsp2_identity_strict`：这个信号是否更像真正的高质量二类买卖点。
- 学习 `label_pre_confirm_invalid`：第三段确认前是否容易结构失效。
- 学习 `label_bsp2_realtime_path`：后续更可能走向哪类实时路径。

当前主线重点不再是用第一层概率硬过滤，而是用二级决策结果参与仓位和风险控制。

## 7. 出场状态机

核心回测逻辑位于：

```text
ML/routes/btc_futures_v2_bsp2_family/backtest.py
```

当前正式出场模式：

```text
family_realtime
```

处理顺序：

1. 如果入场时已经是 `bsp2_t3_overlap` 或 `2,3a` / `2,3b`，视为第三段已确认。
2. 普通二类族群先观察是否触及结构失效位。
3. 如果先回到原中枢目标位，则按回中枢目标出场。
4. 如果先走出第三段确认，则移动保护止损。
5. 第三段确认后，不再使用第三段后时间超时退出，等待 15m 同级别任意反向买卖点出场。
6. 第三段确认前仍保留弱确认超时逻辑，避免无限等待坏结构。

当前明确保护项：

```text
不要随意改 third_confirmed 后的 15m opposite_bsp 出场路径。
```

之前分析过，这条路径是核心利润来源。

## 8. 结构风险定仓

结构风险定仓位于：

```text
ML/shared/structure_position_sizing.py
```

它不是过滤信号，而是根据信号质量调仓位。

主要输入：

```text
bsp2_identity_prob
bsp2_pre_invalid_prob
bsp2_path_prob_invalid_before_confirm
bsp2_path_prob_weak_no_confirm
structure_risk_pct
多周期冲突
回撤比例
分型支撑距离
中枢边界对齐
```

当前分层：

- A 类：结构好、失效概率低、身份概率高，可以更大仓位。
- B 类：中等质量，正常仓位。
- C 类：低质量但仍保留交易，用低仓位参与。

这一步是为了解决“直接过滤会让交易频率下降”的问题。

## 9. 仓后管理

仓后管理相关能力现在集中在：

```text
ML/routes/btc_futures_v2_bsp2_family/post_management.py
ML/shared/post_exit_management.py
```

做过的方向：

- L3 持仓快照。
- 多头/空头分别训练持仓质量模型。
- 多头/空头仓后生命周期特征。
- 多头/空头多头输出：初始止损风险、持仓质量、MAE 风险、是否离开 MFE 峰值、是否继续移动止损、是否严格退出。

当前主线里，仓后管理不是第一优先级。优先级更高的是：二类买卖点入场质量和确认前结构失效风险。

## 11. 当前还没解决的问题

目前最大问题仍然是：

```text
realtime_invalid_before_confirm
```

也就是信号看起来像二类买卖点，但还没走出第三段确认前就结构失效。

之前分析过：

- 好信号和坏信号的模型概率差距不够大。
- 模型容易把大部分二类族群都打成高分。
- 坏结构不能简单删除，否则交易频率会明显下降。
- 更合理的方向是继续做“结构质量分层 + 仓位/风险分层 + 只优化确认前失效”，不要破坏第三段确认后的盈利路径。

## 12. 当前不再保留的内容

已经删除：

- 稳定性/严格阈值路线。
- 结构池独立路线。
- 1:1 `label_tp_first` 阈值路线。
- `taxonomy_v1`。
- `hybrid_v1`。

删除原因：

- 它们不是当前二类买卖点主线。
- 部分路线交易频率过低。
- 部分路线引入了过多分支，容易让项目再次变乱。
- 当前研究重点已经收敛到二类买卖点族群。

## 13. 后续建议

下一步如果继续迭代，建议只做一个方向：

```text
优化确认前结构失效风险，不动第三段确认后的出场路径。
```

更具体可以做：

1. 重新分析 `invalid_before_confirm` 交易事件。
2. 找出它们在入场时可见的结构特征差异。
3. 增强二级决策模型对确认前失效的区分能力。
4. 用结构风险定仓处理低质量信号，不直接过滤。
5. 跑 walk-forward，对照 `decision_realtime_v2`。

每次新实验必须先写：

```text
.claude/experiments/*.md
```

再按 spec 实现。
