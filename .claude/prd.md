# 当前阶段 PRD：专业化 Vibecoding 管理

## 背景

项目已经从单纯的缠论库扩展为包含机器学习、Rust 加速、自研回测、Freqtrade 模拟实盘和 TradingView 展示的完整量化系统。早期快速迭代产生过多个实验路线、临时脚本和结果目录，导致后续难以判断哪次改动真正有效。

当前阶段的目标不是新增交易逻辑，而是建立专业化、规范化的开发治理流程，使后续每一次 vibe coding 都可控、可复盘、可回滚。

## 用户目标

作为项目维护者，我希望：

1. 能快速提出交易想法。
2. AI 能把想法转成清晰 spec。
3. 每次实验都能和当前基准对照。
4. 失败实验不会污染项目。
5. 代码、模型、回测结果、实盘配置都有明确边界。
6. Git 中始终有可回滚的稳定版本。

## 本阶段交付物

- `.claude/spec.md`：项目总规格和主线约束。
- `.claude/prd.md`：当前阶段需求说明。
- `.claude/review_checklist.md`：每次代码和实验审查清单。
- `.claude/experiments/README.md`：实验 spec 写法。
- `ML/BASELINE.md`：当前基准版本指标。
- `ML/EXPERIMENT_LOG.md`：实验记录总表。
- `docs/backtest_rules.md`：回测口径。
- `docs/chan_theory_mapping.md`：缠论理论到代码的映射。
- `docs/freqtrade_deploy.md`：Freqtrade 模拟实盘部署边界。

## 非目标

本阶段不做：

- 不新增模型。
- 不修改入场/出场逻辑。
- 不重新训练模型。
- 不启动模拟实盘。
- 不改 Rust 底层算法。

## 成功标准

1. 新增文档能清晰说明当前主线和保护项。
2. 后续任一实验可以按模板执行。
3. Git 工作区干净，并有一次规范化提交。
4. 临时结果、本地配置、数据库、日志继续保持不入库。
