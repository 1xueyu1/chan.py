# Review Checklist

每次实验、模型更新、回测或实盘策略改动完成后，都必须按此清单检查。

## 1. 需求和边界

- [ ] 是否有实验 spec？
- [ ] 是否明确基准版本？
- [ ] 是否明确本次只改哪些模块？
- [ ] 是否明确哪些路径不能动？
- [ ] 是否说明失败后如何清理？

## 2. 缠论理论一致性

- [ ] 信号定义是否仍对应缠论结构？
- [ ] 二类买卖点族群扩展是否有明确结构依据？
- [ ] 出场规则是否读取实时可见结构？
- [ ] 结构失效位是否来自实际缠论元素，而不是随意近似？
- [ ] 多周期或区间套特征是否避免未来数据？

## 3. 标签和未来函数

- [ ] 训练标签可以使用未来窗口，但回测决策不得直接读取未来标签。
- [ ] 入场时间是否是信号可用时间？
- [ ] 特征是否只使用当前和历史数据？
- [ ] 标签列是否在训练外被误用？
- [ ] 自研回测和 Freqtrade 策略是否使用同一套可见信息？

## 4. 回测口径

- [ ] 是否使用 walk-forward 年度验证？
- [ ] 是否记录总交易数、胜率、收益、PF、最大回撤？
- [ ] 是否按实时路径统计交易贡献？
- [ ] 是否和 `ML/BASELINE.md` 对照？
- [ ] 是否检查交易频率是否被无意降低？
- [ ] 是否检查每币种表现？

## 5. 性能和工程质量

- [ ] 是否避免重复计算？
- [ ] 是否复用缓存？
- [ ] 多进程是否只用于可并行的独立任务？
- [ ] Rust 加速和 Python 结果是否一致？
- [ ] 是否通过 `python -m compileall` 或相关测试？

## 6. 项目清洁度

- [ ] 是否删除失败实验代码？
- [ ] 是否删除 smoke/test 临时结果？
- [ ] 是否避免提交 `result/`、`data/`、数据库、日志、本地配置？
- [ ] `ML/MODEL_REGISTRY.md` 是否更新？
- [ ] `ML/EXPERIMENT_LOG.md` 是否记录结论？
- [ ] git commit 信息是否能说明版本意义？
