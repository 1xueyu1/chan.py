## 4. 参数逐项说明（本次实际用到）

> 重点解释“做什么 + 当前值意味着什么”。

### 4.1 数据与基线参数

- `--source-run-id current_model_full_20260326`
  - 作用：指定要复用的训练产物与基线回测结果。
  - 当前值含义：你在和 `current_model_full_20260326` 做一切对比。

- `--source-artifact-kind run`
  - 作用：指定 `source-run-id` 在 `Debug/runs` 下查找。
  - 当前值含义：基线是正式运行产物，不是测试产物。

- `--artifact-kind test`
  - 作用：本次调优输出到 `Debug/tests`。
  - 当前值含义：避免污染正式 run，便于多轮实验。

- `--begin-time 2020-01-01 --end-time 2026-02-28`
  - 作用：回测时间窗。
  - 当前值含义：覆盖较长周期，结果更接近跨周期表现，而非短期偶然性。

- `--symbols ...10个币种`
  - 作用：组合回测标的集合。
  - 当前值含义：结果反映“多币种组合”而非单币种最优。

### 4.2 阈值网格参数

- `--threshold-start 0.50`
- `--threshold-stop 0.70`
- `--threshold-step 0.05`
  - 作用：定义阈值搜索网格。
  - 当前值含义：只评估了 5 个离散点，速度快，但分辨率中等。

### 4.3 并行与性能参数

- `--max-concurrent-runs 2`
  - 作用：同时跑 2 个阈值子任务（外层并发）。
  - 当前值含义：你采用了“多实例并发”策略，显著缩短总耗时。

- `--symbol-workers 4`
  - 作用：每个子任务内部按 symbol 并行 worker 数（内层并发）。
  - 当前值含义：形成“2 * 4”级别并发负载，吞吐和资源占用平衡偏激进。

- `--parallel-mode process`
  - 作用：symbol 级并行用多进程。
  - 当前值含义：更适合 CPU 密集计算，Windows 下要注意进程开销。

- `--resume-existing`
  - 作用：已有 `backtest_metrics.json` 的子run可直接复用。
  - 当前值含义：中断恢复能力开启，避免重复计算。

- `--backtest-fast-mode`
  - 作用：快速模式，减少重型产物，保留关键指标。
  - 当前值含义：追求调参吞吐，不以报告细节为主。

### 4.4 策略执行参数

- `--signal-margin 0.0`
  - 作用：最终触发阈值 = `signal_threshold + signal_margin`。
  - 当前值含义：你只在扫主阈值，没有额外抬高门槛。

- `--cooldown-bars 0`
  - 作用：开/平仓后冷却窗口。
  - 当前值含义：不做冷却，可能提升交易密度。

- `--meta-threshold-by-bsp 3=0.62,sell_3=0.65`
  - 作用：对特定 BSP 类型（含方向组合键）设置覆盖阈值。
  - 当前值含义：
    - 你并非纯“单阈值策略”；
    - 对 `3` 类及 `sell_3` 做了更严格过滤；
    - 扫描阈值时，其他类型跟随扫描值，`3/sell_3`按覆盖值执行。

### 4.5 成本参数

- `--backtest-fee 0.0004`
  - 作用：手续费率。
  - 当前值含义：已纳入真实交易成本。

- `--backtest-slippage 0.0001`
  - 作用：滑点率。
  - 当前值含义：已纳入成交偏差，结果较裸回测更保守。

### 4.6 命名与管理参数

1. `annualized_return_up`: 候选年化 >= 基线年化
2. `max_drawdown_not_worse`: 候选回撤绝对值 <= 基线回撤绝对值 + 容忍值
3. `sharpe_not_down`: 候选Sharpe >= 基线Sharpe - 容忍值
4. `trade_count_in_range`: 候选交易数在 [min, max] 区间

- 0.50：交易数超上限，触发 `trade_count_in_range = false`
- 0.55：年化略低于基线，触发 `annualized_return_up = false`
- 0.60+：收益和交易活跃度都明显不足

所以 `passed_count = 0`，系统只能退化为 fallback 选分最高。

## 6. 如果“收益和约束都重视”，当前结果该怎么用

你可以把本次结果理解成：

1. 0.50 是“收益上限参考点”（偏激进，高交易密度）。
2. 0.55 是“约束友好参考点”（交易数合理但收益略输基线）。
3. 可行优化区间就在 `0.50 ~ 0.55` 之间，不建议继续往 0.60 以上加阈值。

建议下一轮策略：

- 在 `0.51~0.55` 做细网格（步长 0.01）

这样你能得到两条可选曲线：

- 更稳健的“约束优先”参数
- 更进攻的“收益优先但可控”参数
